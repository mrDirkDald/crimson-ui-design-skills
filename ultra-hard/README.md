# Crimson UI Design HARD

## ULTRA-HARD profile

This build is the **ULTRA-HARD** frozen snapshot: the maximum-depth edition with no token-economy constraint when a topic is materially relevant. It adds a large deep-playbook layer under `handbook/ultra/`, while retaining all existing HARD references, platform guides, language/toolkit coverage, QA, web-craft material, and engineering manuals.

ULTRA-HARD is still selective by relevance: it should not load unrelated material for no reason. The difference is that it does not intentionally shorten a relevant design problem into a tiny checklist.


**Crimson UI Design HARD** is the exhaustive, frozen edition of the Crimson UI Design skill.

It is intentionally built for people and agents that do **not** want to optimize for token cost. It keeps the full instruction hierarchy, deep aspect skills, product-pattern handbooks, broad programming-language/toolkit coverage, high-end web-craft guidance, accessibility, tooling, QA, and implementation verification in one package.

## Edition position

```text
Light    → compact, fast, actively maintained
Standard → balanced canonical edition, actively maintained
HARD     → exhaustive, token-unconstrained, frozen snapshot
```

## What “HARD” means

HARD does not mean “add more effects.” It means:

- inspect more evidence before making design claims;
- keep more specialized instructions available;
- route into multiple aspect subskills when the problem spans them;
- support a very broad language/toolkit matrix;
- give high-end web craft its own deep instruction set;
- include implementation, accessibility, product, QA, performance, release-readiness, and tooling guidance;
- verify the real rendered/runtime result instead of trusting code appearance;
- explicitly preserve working behavior during redesigns.

## Web craft

HARD contains the full human-vs-AI web-craft analysis and additional detailed web-craft handbooks covering page architecture, typography, media, motion, conversion, responsive recomposition, anti-template diagnosis, performance, accessibility, interaction, and whole-page QA.

## Language/toolkit coverage

No programming language is excluded. Explicit language guides cover the major ecosystems, while an unknown-stack fallback classifies the UI architecture first and maps universal design rules to the toolkit's real primitives.

## Icon baseline

1. Preserve an existing coherent project icon system.
2. Otherwise use Lucide Icons for general-purpose UI where technically suitable.
3. Use compatible custom SVG/vector icons for domain/brand-specific concepts.
4. Do not use emoji as UI icons.

## Tooling

HARD includes optional tooling guidance for runtime/UI verification, accessibility, performance, project-native tests, Playwright, Storybook/component harnesses, `fchek`, `skill-check`, `npm-safe`, and related diagnostics. Tools are selected only when they answer a concrete question.

## Frozen policy

```text
STATE: FROZEN
SELF-UPDATE: DISABLED
AUTO-SYNC WITH STANDARD/LIGHT: DISABLED
```

HARD deliberately contains no automatic updater. Standard and Light are the active editions. HARD changes only when the user explicitly requests a new frozen snapshot.
