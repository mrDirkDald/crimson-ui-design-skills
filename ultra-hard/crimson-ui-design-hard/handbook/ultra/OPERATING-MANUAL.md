# Crimson UI Design ULTRA-HARD Operating Manual

ULTRA-HARD is a frozen, maximum-depth profile of HARD. It intentionally does **not** optimize for prompt length, reference count, or token efficiency when those savings would remove material design reasoning.

## Principle

Token economy is subordinate to:

1. correct product understanding;
2. preservation of working behavior;
3. explicit state and failure modeling;
4. platform/toolkit correctness;
5. accessibility;
6. product-specific structure and visual identity;
7. responsive/adaptive behavior;
8. implementation integrity;
9. runtime evidence;
10. visual craft.

The agent should still avoid irrelevant material. “No token economy” does not mean “load every file every time.” It means: when a topic materially governs the task, do not collapse it into a shallow summary merely to be short.

## Deep-read routing

For a meaningful redesign or implementation, select all materially relevant layers:

```text
ROOT CONTRACT
+ PRODUCT / TASK MODEL
+ DESIGN FOUNDATION
+ SURFACE TYPE
+ PLATFORM
+ LANGUAGE / TOOLKIT
+ COMPONENT-SPECIFIC GUIDES
+ STATE / ERROR / RECOVERY GUIDES
+ ACCESSIBILITY
+ PERFORMANCE
+ QA / RUNTIME VERIFICATION
```

For a beautiful website, a typical deep route is:

```text
SKILL.md
→ references/web-craft-analysis.md
```

## No shallow completion

A result is not complete merely because:

- the default screenshot looks polished;
- the build succeeds;
- the CSS compiles;
- one viewport works;
- mouse interaction works;
- the happy path works;
- a component library is internally consistent;
- an AI self-score says the design is strong.

Completion requires the relevant acceptance criteria and runtime evidence for the actual task.
